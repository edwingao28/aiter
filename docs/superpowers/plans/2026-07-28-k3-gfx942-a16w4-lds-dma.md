# Kimi K3 gfx942 A16W4 LDS DMA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the current Kimi K3 A16W4 SiTUv2 FlyDSL kernels compile and run numerically on MI300X.

**Architecture:** Keep the current mixed-MoE dequantization, BF16 MFMA, and SiTUv2 implementation. Introduce a dependency-free DMA-width policy and use it in both A16W4 stages so gfx942 emits legal 4-byte global-to-LDS operations while existing architectures keep their current 16-byte path.

**Tech Stack:** Python, FlyDSL, ROCm LLVM, pytest/unittest, MI300X.

---

**Files:**

- Create: `op_tests/flydsl_tests/test_lds_dma_policy.py`

- [ ] Write a dependency-free unit test that requires gfx940/gfx941/gfx942
  (including feature suffixes) to select 4 bytes, gfx950/gfx1250 to retain 16
  bytes for divisible copies, and invalid non-dword copy sizes to raise.
- [ ] Run `python3 -m unittest op_tests.flydsl_tests.test_lds_dma_policy -v` and
  verify it fails because the policy module does not exist.
- [ ] Implement `select_raw_ptr_buffer_load_lds_bytes(gpu_arch,
  bytes_per_thread)` with the exact behavior above.
- [ ] Rerun the unit test and verify it passes.
